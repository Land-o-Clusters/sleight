# What works in the background

Each row is one kind of action. "Background" means the app can be behind your other windows while you
keep the pointer and keyboard. Every count comes from a linked result file or doc, as of
2026-10-09. Where nothing measured a cell, it says "not measured".

| Action | Background (your pointer and keyboard untouched) | Takes the pointer or focus | Evidence |
|---|---|---|---|
| Read the window's tree | yes | no | 5/5 full reads at load 135, 0 stops ([load-cost-interleaved](benchmarks/2026-10-09-load-cost-interleaved.json), 2026-10-09) |
| Screenshot | yes | no | 9/9 runs of chess-drag, simulator-form and textedit-drag, owner away ([shots-base](benchmarks/2026-10-09-shots-base.json), 2026-10-09); some Chess captures came back black ([reliability](benchmarks/2026-10-08-reliability.md), 2026-10-08) |
| Click an element | yes | no | 3/3 calculator-click with the owner using the Mac ([h2h-background](benchmarks/2026-10-09-h2h-background.json), 2026-10-09); 5/5 eight-click calls with 0 stops at loads 20 to 79 ([load-cost-interleaved](benchmarks/2026-10-09-load-cost-interleaved.json)) |
| Click at coordinates | yes | no | 3/3 simulator-form taps with the owner using the Mac ([release-0.16.0](benchmarks/2026-10-09-release-0.16.0.json), 2026-10-09); the first tap left Safari's field unfocused in 6/6 runs ([known problems](known-problems.md#specific-apps)) |
| Type text | yes | no | 3/3 textedit-save with the owner using the Mac ([h2h-background](benchmarks/2026-10-09-h2h-background.json)); `typeText` goes through macOS auto-capitalization (1/1 probe, 2026-10-08, [known problems](known-problems.md#specific-apps)) |
| Keys and shortcuts | yes | no | 5/5 calls of one click and three keys ([load-cost-after-skip](benchmarks/2026-10-09-load-cost-after-skip.json), 2026-10-09); 3/3 textedit-edit with the owner using the Mac ([h2h-background](benchmarks/2026-10-09-h2h-background.json)) |
| Paste | yes | no (`app.paste` borrows your clipboard and puts it back) | all bytes restored in 4/4 fixtures ([clipboard](benchmarks/2026-10-04-clipboard.md), 2026-10-04); 3/3 textedit-calculator copy and paste, owner away ([real-use-tasks-8](benchmarks/2026-10-09-real-use-tasks-8.md)); in the simulator a paste inserted the Mac's clipboard (2026-10-07, [known problems](known-problems.md#specific-apps)) |

| Drag elsewhere (Chess, Finder) | sometimes (the engine's `app.drag` moved a pawn through a covered window 1/1, where sleight's posted drag went 0/2) | sometimes (when the private window-location API is missing; a covered drag with no selected text is now refused, and before that Finder took the foreground path 3 times in round 6) | [known problems](known-problems.md#the-pointer-drags-and-hover), 2026-10-09; 1/1 posted e2-e4 while the pointer moved ([background-drag-product](benchmarks/2026-10-04-background-drag-product.md), 2026-10-04); 3/3 chess-drag, owner away, path not recorded ([release-1.1.0](benchmarks/2026-10-09-release-1.1.0.json)); 3/3 finder-files ([real-use-tasks-8](benchmarks/2026-10-09-real-use-tasks-8.md)) |
| Hover | no (posted mouse moves fired no enter or exit, 2026-10-04; tooltips read as `Help:` text without hover) | yes (`hover` brings the app forward and moves the pointer, after 2 s without your input) | tooltip absent at 400 and 1000 ms, readable at 1500 ms (1/1 each); takeovers 1786 to 1798 ms ([local-hover](benchmarks/2026-10-04-local-hover.md), 2026-10-04) |

| Apps in another Space or full screen | sometimes (clicks and typing reach them; drags fail and TextEdit reads timed out) | no (`drag` refuses an off-screen window) | Calculator 6/6 and all tasks 13/21 with the Claude app in Split View ([await-split-view](benchmarks/2026-10-08-await-split-view.json), 2026-10-08); textedit-drag 0/2 behind a full-screen app, as expected ([full-screen-every-read](benchmarks/2026-10-09-full-screen-every-read.json), 2026-10-09) |
| Terminals and OpenAI's apps | sometimes (`blocked_app` reads, element presses and scrolls stay in the background; the engine refuses these apps) | yes for typing, keys and point clicks (the app comes forward, then your front app and pointer go back) | Terminal read 4/4 after approval, and a typed command ran in 1 of those 4; ChatGPT read 2/2, exposing only window controls (13 runs in `benchmarks/2026-10-04T*-blocked-*.json`, [design](design/blocked-apps.md)) |

Pointer position was sampled only in the drag trials. Other "yes" cells rest on runs that passed with
the app in the background, with the owner using the Mac where noted and away otherwise.
All runs are on one Mac, mostly 3 per task with Sonnet 5.5 at medium effort.
Your own input in the app Claude is driving interrupts it: the engine notices and makes Claude re-read.
With 20 CPU-bound workers (load 12 to 137), sleight passed 2 of 5 runs ([h2h-loaded](benchmarks/2026-10-09-h2h-loaded.json)).
