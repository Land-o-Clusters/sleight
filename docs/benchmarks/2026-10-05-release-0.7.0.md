# Benchmark for 0.7.0 (2026-10-05)

Every run made for the release, failures included, is in
[2026-10-05-release-0.7.0.json](2026-10-05-release-0.7.0.json). sleight arm only, Sonnet 5.5 at medium
effort, Claude Code 2.1.289, engine 26.930.31730. The owner was away from the Mac for all of it.

| Pass | Result | What it showed |
|---|---|---|
| First attempt | 0/2, then 0/1 twice | The engine's helper wouldn't launch |
| Full pass | 13/18 | Bundle IDs missing from the allowlist, off-desktop windows, an Open panel stall |
| TextEdit and Chess rerun | 11/12 | textedit-drag 3/3 once TextEdit's windows were on screen |
| Clean full pass | 16/18 | Arm folder outside the repo; chess-drag 1/3 |

## Clean full pass

| Task | Passed | Median s |
|---|---|---|
| calculator-click | 3/3 | 40.6 |
| calculator-menu | 3/3 | 55.9 |
| textedit-save | 3/3 | 56.2 |
| textedit-edit | 3/3 | 29.6 |
| textedit-drag | 3/3 | 44 |
| chess-drag | 1/3 | 66.5 |

All three text drags took the foreground path, because this Claude window covered TextEdit on the
second display and the tool skips the background attempt then. In the rerun 2/3 moved in the
background, and 1/3 went to the foreground because this window covered TextEdit.

Both Chess failures aimed at the wrong square. Each drag from e2 ended near y = 475 in the
screenshot, which is e5, an illegal first move, so the board didn't change. The passing run ended
at y = 545, on e4. The rerun's failure aimed at y = 470 to 485 the same way. Both the engine's
`app.drag` and sleight's `drag` were tried at those points.

## Problems found before the clean pass

- The helper wouldn't start. Every app call returned "Sky Computer Use service startup request
  failed", while `--doctor` reported "live read ok". launchd kept the job of a helper that had quit
  normally and refused new launches with "Operation already in progress". `launchctl remove` of
  that job fixed it without restarting ChatGPT. Doctor now reports the failure and prints the command.
- The approval hook only knew the apps' names. Input leases have Claude acquire apps by bundle ID,
  so a `drag` in `com.apple.Chess` was declined (full pass, chess-drag #1). The allowlist now has
  the same three apps' bundle IDs.
- TextEdit opened the benchmark documents on another desktop, and `drag` refused them as off
  screen (full pass, textedit-drag #2 and #3). Each TextEdit task now quits TextEdit first when it
  has no open documents.
- TextEdit's Go to Folder sheet stayed on "Loading…" in textedit-edit #1 and textedit-drag #1 of the
  full pass, so Claude never opened the file. It didn't happen again after the setup change, but we
  don't know the cause.
- The arm folder `.dev/sleight-arm` sat inside this repo. Claude Code loads CLAUDE.md from parent
  folders and keys project memory by the git root, so every run before the clean pass got the
  repo's CLAUDE.md and memory, and one Chess run read a memory file. That has been true since
  2026-10-03 for both arms. The benchmark now refuses an arm folder inside a repo.
