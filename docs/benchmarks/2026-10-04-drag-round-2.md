## Changes and limits

The AX content walk now refuses above 300 elements or 12 levels. Its refusal happens before mouse-down,
and the helper's cleanup restores the pointer and previous front app. A test supplies 1,000 extra
elements and verifies the bounded walk and focus restoration. It asserts an empty mouse event list.

An element cap cannot prevent one AX call from hanging. The launcher captures the prior
front app's process ID before starting the drag child. It attempts restoration from a separate
AppKit helper when the drag returns, throws or reaches its 30 s timeout. Cleanup has its own 3 s
timeout and runs even when the session is closing. It restores only while the target is still
frontmost. Another app taking focus wins. Shutdown waits for each pending drag's cleanup, including
restoration helpers launched after cancellation. Cleanup failure returns an error, preserving the
drag's original error. Unit tests cover these paths and the native capture/restore boundary.

Refusals now append “nothing was pressed” once. The README keeps the counts and limits.
It marks the benchmark as preceding the guards. Chess and Calculator content guards remain unmeasured.
The skill uses the measured 4.5 s instead of two seconds.

No live app run occurred in this round. A new owner-away confirmation was requested for Chess
e2 to e4 and Calculator. No reply had arrived when these changes were verified. The unmeasured
apps remain in Known problems, as the review permits. No app roles were widened without evidence.
The earlier two-window reproduction limitation remains recorded in the
[window report](2026-10-04-drag-window-guards.md). This round used unit tests only.
